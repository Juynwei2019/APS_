# APS｜先進規劃與排程系統

APS（Advanced Planning and Scheduling）專案旨在協助製造現場整合訂單、產能與生產限制，產生可執行的生產排程，並讓使用者比較排程結果與調整生產計畫。

> 目前已提供可執行的單廠 APS MVP：繁體中文網頁介面、SQLite 資料保存與有限產能排程。採用 Python 標準函式庫及原生 JavaScript，無執行期第三方依賴。

## 專案目標

- 依訂單交期、優先順序與可用產能安排生產。
- 納入工序先後、設備可用時間與物料到位等限制。
- 呈現設備負荷、預計完工時間與交期風險。
- 支援人工調整與重新排程，協助處理急單或設備異常。

## 第一階段：最小可用版本（MVP）

先建立單一工廠的有限產能排程流程，讓使用者能從基本資料得到可檢視的排程結果。

| 模組 | 已實作範圍 |
| --- | --- |
| 基本資料 | 產品、設備、設備工作日曆與製程路線 |
| 訂單管理 | 訂單數量、交期與優先順序 |
| 工單與工序 | 工單拆解、工序順序與加工時間 |
| 排程引擎 | 依設備產能及工序先後進行排程，避免設備時段重疊 |
| 結果呈現 | 排程清單、設備甘特圖與逾期提示 |
| 排程調整 | 修改訂單或設備可用時間、儲存後重新計算 |

物料限制、換線時間、多工廠協同與 ERP／MES 串接可於後續階段評估。

## 預計操作流程

1. 建立設備、工作日曆、產品與製程路線。
2. 輸入訂單，建立對應工單及工序。
3. 設定排程期間與訂單排序規則。
4. 執行排程，檢查設備負荷、完工時間與未能排入的工序。
5. 調整資料或條件，重新排程並比較結果。

## 核心資料概念

| 資料 | 說明 |
| --- | --- |
| 訂單（Order） | 客戶需求，包含產品、數量、交期與優先順序 |
| 工單（Work Order） | 依訂單建立的生產任務 |
| 工序（Operation） | 生產步驟，包含前置工序、可用設備與預計加工時間 |
| 資源（Resource） | 執行工序的設備或工作中心 |
| 工作日曆（Calendar） | 資源可工作的時段、休假及停機時間 |
| 排程結果（Schedule） | 工序配置的資源、開始時間與結束時間 |

## 排程驗證原則

第一階段應以小型、可人工核對的案例驗證下列行為：

- 同一設備的工序時段不得重疊。
- 後續工序必須在前置工序完成後開始。
- 工序安排必須符合設備工作日曆。
- 無法排入的工序需呈現原因，不能直接省略。
- 完工時間超過訂單交期時需標示逾期。
- 相同輸入與設定應產生可重現的結果。

## 開發規劃

1. **需求確認**：確定適用產業、製程範例、排程單位與時間精度。
2. **資料設計**：定義基本資料、訂單、工序及排程結果的結構。
3. **排程原型**：以小型範例實作有限產能排程與限制驗證。
4. **操作介面**：提供資料輸入、排程執行及結果檢視。
5. **情境驗證**：測試急單、產能不足、休假及設備停機情境。

## 開發環境與啟動方式

需求：Python 3.10 以上及現代瀏覽器。無需安裝第三方套件或設定環境變數。

在儲存庫根目錄執行：

```bash
python app.py
```

伺服器預設使用本機 `127.0.0.1:8000`；可用 `--port 8080` 指定其他連接埠。開啟瀏覽器，輸入該本機位址即可操作。此伺服器供本機開發使用，尚未提供登入、權限與正式部署機制。

首次啟動會建立 `data/aps.db`，並載入兩台設備、一種產品與兩張訂單。後續重啟會保留資料，不會覆寫成範例。資料庫與快取已列入 `.gitignore`；備份時請先停止伺服器，再複製資料庫。

### 試用步驟

1. 在「設備與日曆」新增或調整明確的可用起訖時段。未列入的時間視為不可用，可藉此表示休假或停機；同一設備的時段不可重疊。
2. 在「產品與製程」建立按順序執行的工序，指定設備與單件加工分鐘。
3. 在「生產訂單」輸入產品、數量、優先順序（1 最高）與交期。MVP 將每張訂單視為一張工單。
4. 按「儲存資料」，設定排程起訖與排序規則，再按「產生排程」。
5. 檢查設備甘特圖、訂單交期與工序明細。修改資料後儲存，再排程即可比較結果。
6. 可匯出目前畫面的 JSON；「載入範例」需確認，且只有按儲存後才會覆寫資料庫。

### 排程規則與限制

- 使用工廠當地時間，精度為分鐘；所有輸入須採用同一時區，不接受時區偏移或秒數。不處理日光節約時間切換。
- 可依優先順序或交期排序，以訂單識別碼作為最後的穩定排序條件。
- 每道工序使用一台指定設備，加工時間為「數量 × 單件加工分鐘」。
- 工序不可跨休息時段或拆段加工；只有整段可用產能足夠時才能排入。
- 工序依製程順序執行，設備時段不重疊。不同設備可同時加工不同訂單。
- 前置工序未排入時，後續工序也會列為未排入並註明原因；已排入的前段工序仍保留。
- 採用依排序規則逐單安排的啟發式演算法，提供可行排程，不保證全域最佳解。
- 尚未支援物料、人員、模具、換線、替代設備、手動拖曳工序、多使用者協作與歷史版本比較。

### 驗證

必要的排程與 HTTP API 測試（不需要第三方套件）：

```bash
python -m unittest discover -s tests -v
```

選用的瀏覽器操作測試，需要 Playwright 與 Chromium：

```bash
python -m pip install playwright
# 指定已安裝的 Chromium 執行檔；此路徑依作業系統調整
APS_CHROMIUM=/usr/bin/chromium python tests/browser_smoke.py
```

瀏覽器測試會啟動獨立伺服器及暫存資料庫，驗證排程、甘特圖、錯誤提示、儲存後重新載入及手機版面，不影響開發資料。

### 專案結構

```text
app.py                  HTTP API 與 SQLite 儲存
scheduler.py            排程引擎與資料驗證
sample.py               初始範例資料
static/                 網頁、樣式與操作邏輯
tests/                  排程、API 與選用瀏覽器測試
data/aps.db             本機資料庫（不提交）
```

### API

| 方法與路徑 | 用途 |
| --- | --- |
| `GET /api/data` | 讀取已保存的設備、產品與訂單 |
| `POST /api/data` | 驗證並完整保存資料，格式參考 `sample.py` |
| `GET /api/sample` | 取得依伺服器當天日期產生的範例，不直接保存 |
| `POST /api/schedule` | 對已保存資料排程，傳入 `start`、`end` 與 `rule`（`priority` 或 `due`） |

## 待確認事項

- 適用產業與主要生產模式（例如離散製造或批次生產）。
- 排程目標：降低逾期、縮短生產週期或提高設備利用率。
- 工序是否可中斷、是否允許替代設備及平行加工。
- 時間精度、班別、時區與加工時間的計算方式。
- MVP 是否必須納入物料、換線、人員或模具限制。
- 正式部署方式、登入權限及多人協作需求。
- 使用者角色、資料來源與外部系統串接需求。
